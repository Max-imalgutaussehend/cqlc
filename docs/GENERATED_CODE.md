# The generated code

`cqlc generate` writes one Rust module. Declare it with `#[rustfmt::skip] mod queries;`.
It needs the crates `scylla`, `uuid`, and, depending on your queries and settings, `chrono` (with
scylla's `chrono-04` feature) and `futures`.

## Per query

For a query `-- name: GetUserById :one`:

| Item | Description |
| --- | --- |
| `GET_USER_BY_ID_CQL` | the normalized CQL text |
| `GetUserByIdRow` | result row, `:one` and `:many` only |
| `GetUserByIdParams` | bind values, only if the query has two or more |
| `GetUserByIdOutcome` | result of a `:lwt` query |
| `get_user_by_id(session, ..)` | prepares the statement and runs it |
| `stream_get_user_by_id(session, ..)` | `:many` only, returns a `BoxStream` |

One parameter is a plain argument, several become the `Params` struct. Parameter names come from
the column; when a column is bound more than once the role is added (`created_at_gte`,
`created_at_lt`, `stock_new`, `stock_if_eq`).

## Preparing once

Each free function prepares its statement on every call. For repeated use, create `Queries`
once:

```rust
let queries = Queries::new(std::sync::Arc::new(session)).await?;
let user = queries.get_user_by_id(id).await?;
```

`Queries` prepares every statement up front and has a method for each query (and `stream_`
variant). It does not cache anything else; the driver handles connections, retries and routing.

## Errors

Every function returns `CqlcError`: the query name, the failed stage (`Prepare`, `Execute`,
`Rows`, `Deserialize`) and the driver error as `source()`. Driver types never appear in your
signatures.

## Null, absent and unset

* **Results:** primary key columns are never null. Every other column is `Option<T>`.
* **Binds:** regular columns written by `INSERT` or `SET` take `Option<T>`; `None` binds **NULL**
  and writes a tombstone. "Leave unset" does not exist; leave the column out of the statement.
* Partial updates (`col = col + ?`, `col[?] = v`) never take NULL.

## `:one`, `:many` and streams

`:one` returns `Option<Row>`. The query is expected to match at most one row; if it matches more,
the first is returned (cqlc cannot verify cardinality).

`:many` loads the whole result into memory. For large results use the `stream_` variant, which
pages through the data:

```rust
use futures::TryStreamExt;
let mut rows = queries.stream_events(tenant).await?;
while let Some(row) = rows.try_next().await? {
    // one row at a time
}
```

## Lightweight transactions

A `:lwt` query returns an outcome, never an error for a failed condition:

```rust
let out = queries.ship_order(params).await?;
if !out.applied {
    println!("current status: {:?}", out.status);
}
```

`applied` is the conditional result. When it is false, the fields hold the values currently
stored in the tested columns (`IF NOT EXISTS` reports the whole row). Cassandra and ScyllaDB
report different column sets for a failed write; the generated code handles both.

## User-defined types

A used `CREATE TYPE` becomes a struct deriving the driver's `SerializeValue` and
`DeserializeValue`. All fields are `Option<T>`. Types that are not used by any query are not
generated.

## Stability

The shape of the generated code is versioned by the *output format* in the file header
(`// @generated by cqlc (output format 1)`). It changes only in a new major version of cqlc, so
upgrading within a major version never changes generated files unless your queries changed.
